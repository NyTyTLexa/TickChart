# TickChart

Контрол Avalonia для отрисовки тиковых данных в реальном времени на базе ScottPlot.
Сделан как тестовое задание: отдельная библиотека с `TemplatedControl` и демо-приложение
с генератором цены.

Требования задания: до 10 000 точек на графике, до 100 новых точек в секунду,
окно видимых точек и тема настраиваются из XAML.

.NET 8 · Avalonia 11.3 · ScottPlot 5 · MVVM

https://github.com/user-attachments/assets/5932756f-1d05-4c93-bc89-e10f00b14533

## Использование

```xml
<Window xmlns:controls="clr-namespace:TickChart.Controls;assembly=TickChartControl">
    <controls:TickChart Name="TickChart" MaxVisibleTicks="500" Theme="Dark" />
</Window>
```

```csharp
TickChart.AddTickData(timestamp, price);   // одна точка, из любого потока
TickChart.AddTickDataBatch(ticks);         // пачка точек
TickChart.ClearData();
```

| Свойство | По умолчанию | Что задаёт |
|---|---|---|
| `MaxVisibleTicks` | `500` | сколько последних точек держать на графике |
| `Theme` | `Light` | `Light` или `Dark`: фон, область данных, оси, сетка |

## Как устроено

- **Поступление данных отделено от отрисовки.** Точки складываются в буфер под блокировкой,
  а перерисовку раз в 16 мс (около 60 кадров в секунду) делает таймер с фоновым приоритетом
  диспетчера. 100 точек в секунду не превращаются в 100 перерисовок.
- **Вызов из любого потока.** Если метод вызван не из UI-потока, работа переносится
  в `Dispatcher.UIThread` — генератор данных может жить где угодно.
- **Скользящее окно.** Пока точек меньше `MaxVisibleTicks`, график растягивается на всю
  ширину. Сверх лимита старые точки отбрасываются. Если лимит уменьшить на ходу,
  буфер обрезается сразу.
- **Значение лимита кешируется в поле,** чтобы таймер не читал `StyledProperty`
  из фонового потока.

## Демо-приложение

- **Start / Stop** запускает и останавливает генерацию случайного блуждания цены.
- **NumericUpDown** меняет `MaxVisibleTicks` от 100 до 1000 с шагом 50.
- **ComboBox** переключает тему.

dotnet run --project UTS.AvaloniaUI.ComponentTask1
